## 1. 方法

产品定义走**决策门**（decision gate）流程，共 11 道门。每道门：

1. Claude 铺陈选项与取舍，不给结论
2. Qian 做选择
3. Claude 推演该选择的**派生后果**，并立即用后果反向检验前面的决策

工具上用了三样成熟方法：Jobs-to-be-Done 定核心循环、MoSCoW 切范围、ADR 记录技术取舍。

设计约束（由 Qian 提出）：决策必须是他自己的，Claude 负责铺陈和推演，不负责替他拍板。

## 2. 决策门时间线

### D1 — 目标与优先级

| | |
|---|---|
| **决策** | 首要：自用便利。次要：开源影响力。非目标：技术创新、收入 |

### D2 — 成功指标与时间预算

| | |
|---|---|
| **选项** | 连续打卡 21 天 / 读完 SICP 第一章并通过复习题 / 主观体感 / 代码可复用 |
| **决策** | **连续打卡 21 天不断签**；每日投入 10–15 分钟 |
| **为什么重要** | 这是全项目唯一验收标准。选"连续性"而非"完成度"，意味着**降低每日摩擦**压过一切其他考量 |

**后果 1**：21 天 × 12.5 分钟 ≈ 4.4 小时。SICP 第一章需 15–25 小时，两者对不上（见 D8 的重新处理）。
**后果 2**：任何可能让 session 超时或失败的环节都威胁成功指标 → 强烈倾向构建期预生成，排斥运行时 LLM 调用。

---

### D3 — 核心循环

| | |
|---|---|
| **决策** | 读新内容每日必做；复习内容由遗忘曲线模型智能决定，非固定题量 |
| | 打卡判定 = 阅读满时长（用户可设）+ 完成题目；答错显示答案并标记为不熟悉 |
| | 断签**只记录不惩罚**，但必须有打卡可视化 |

**后果 3（产品定位改变）**：Duolingo 的 streak 靠损失厌恶驱动，断签清零产生痛感。选了"不惩罚"就等于否掉了这个机制，动机源换成进度可视化 + 复习闭环的正反馈。
→ **类比对象从 Duolingo 改为 Anki + 阅读日历。** 后续所有 UI 决策据此。

**后果 4**：题目必须分两类。若只有到期复习题，某天到期数为 0 会让"完成题目"这一打卡条件悬空。故需要"新内容理解题"作为保底。

**后果 5**：复习债务是这类产品的头号失败模式（Anki 经典）。15 分钟预算下到期项只增不减，两周后队列爆炸就会弃用。

---

### D4 — 内容模型（分四小门）

#### D4a 内容切分

**决策**：用户设定每日阅读时长，LLM 语义切分、小节边界优先；**每日时长目标可随时调短**。

**后果 6（架构级）**：时长可动态调整 ⇒ 内容**不能预切成固定的"每日单元"**——调整目标后预切结果即作废。
→ 只能切成**原子块**（2–3 分钟、语义完整、不跨小节），运行时按当前目标动态打包。
→ 代价：LLM 切分时须额外产出每块的**预估阅读时长**。

#### D4b 知识点来源

**决策**：LLM 基于内容理解生成知识点列表；答错的题记录并按遗忘曲线纳入未来复习。

#### D4c 内容制品形态

| 方案 | 结果 | 理由 |
|---|---|---|
| 结构化 JSON/Markdown 包 | ✅ 选中 | `fetch()` 直读零依赖；可 diff；内容包目录可分离分发（版权隔离） |
| 运行时解析 epub | ❌ | LLM 切分/出题是构建期昂贵操作，不可能放运行时；知识点仍需另存，方案退化为"JSON 包 + 多一层解析" |
| SQLite | ❌ | 数据量级（数百块）内存过滤即可；二进制不可 diff，浏览器还要 wasm ~1MB |

同时确立：**内容制品**（只读、构建期产出）与**用户状态**（读写、运行时产出）是两类数据，存储选型可分开。

#### D4d 生成 / 阅读边界

> 由 Qian 主动提出的问题："能否让用户在本地解析自己的 epub 生成内容包，还是只有我能生产？"

分析：阶段二是无后端静态站。浏览器内生成需要调 LLM，而 API key 无处安放——用户自带 key 门槛劝退，key 打进前端会被刷爆，加代理就不是静态站了。

**决策**：**彻底解耦**成生成器与阅读器两个组件，以内容包 schema 为唯一契约。

**后果 7**：schema 必须带 `schema_version`，否则生成器升级会静默打断旧包。
**后果 8（关键）**：阅读器若要联网生成就必须知道生成规则，解耦即破 ⇒ **阅读器绝不调 LLM**。这把后果 2 的"倾向"升级成了硬性架构约束。

---

### D5 — 复习调度

| | |
|---|---|
| **决策** | 阶段一用固定间隔 Leitner，但**调度器做成可替换的策略接口** |
| | 债务控制：错题优先，超预算的到期项**视同未到期、明天继续排队**（不视同答对） |
| | 错题复习**只重复原题**，不预生成变体 |

**选型理由**：21 天窗口内任何间隔 > 21 天的分支都不会执行，Leitner / SM-2 / FSRS 在成功指标下无法区分优劣。重要的是保留替换能力。

**"丢弃"的语义歧义**（Claude 提出、Qian 裁决）：
- (a) 视同已复习答对 → 间隔照常延长 → 产生**虚假掌握**，知识点可能再也不出现 ❌
- (b) 视同未到期 → 明天继续排队 ✅ 选中，代价是积压会发生

**后果 10**：只重复原题 + 错题优先 ⇒ 撞上 Anki 的 **leech 问题**（记住答案字面而非知识点）。
**后果 11**：新内容题排队列第一 ⇒ 保证打卡条件永不悬空，但复习被系统性挤压，长期"读得多记得少"。缓解：新内容题严格锁 2 道。
**后果 12**：顺延语义 ⇒ 需要"待复习积压数"作为观测手段，否则用户无从判断该不该调低每日新内容量。

### D6 — 范围与技术选型

**v0.1 范围**：断点续读、前一日内容摘要回顾、**异常退出时保证阅读记录不丢失**（Qian 主动补充的需求）。
复习健康度提示、多本书并行切换归入阶段二。

**技术选型**：生成器 Python，阅读器 TypeScript。

> 选型的前提是 D4d 的解耦——生成器永不进浏览器，阅读器需两端共用，**两个组件用不同语言不是妥协而是解耦的红利**。

**后果 13（架构级，由"异常退出不丢记录"驱动）**：用户状态应做成 **append-only 事件日志（JSONL）**而非可覆盖的状态快照。
附带解决了一开始就想要的**多端同步**——快照文件合并会产生"哪边赢"冲突，事件日志按 `(ts, id)` 去重排序即可合并。

**后果 14**：双语言 ⇒ JSON Schema 作为单一真相源，Python 用 pydantic、TS 用 zod/ajv 各自生成校验器，否则字段定义会漂移。

### D7 — 题型 / 仓库 / CLI 形态

| | |
|---|---|
| **题型** | 仅用选择题。概念题或代码片段皆可，但一律给选项，**不要求用户输入文本** |
| **内容包位置** | 同仓 + `.gitignore` 排除私有包 |
| **CLI 形态** | 单命令一次性流程 + 系统 pager 显示正文 |

**后果 16**：全选择题 + 只重复原题 ⇒ **选项必须运行时随机打乱**。否则重复几次后记住的是"答案在 B 位"——这正是 leech 最常见的形式。一行代码消掉 R3 的大半。
**后果 17**：选择题可靠排除法蒙对，唯一防线是干扰项 ⇒ **干扰项质量成为生成器核心指标**，prompt 必须要求干扰项为常见误解。
**后果 18**：pager 顺带解决计时锚点——进入到退出 pager 的时长即该块阅读时间，无需手动开始/结束。网页版对应"block 可见时计时"。
**后果 19**：`.gitignore` 对**已 tracked 文件无效**。私有包一旦被 `git add` 过就拦不住 ⇒ 强制顺序：先 gitignore 再放内容包，禁用 `git add -A`。

排除 TUI 的理由：成本高，且 TUI 代码阶段二一行用不上，叠加 TypeScript 学习成本是明显的时间陷阱。
断点续读在单命令模式下**天然成立**（退出即断点），无需额外设计。

---

### D8 — 首本书 / 生成器调用 / 新内容题数量

| | |
|---|---|
| **首本书** | SICP **第一章**（非仅 1.1 节）；乔布斯传阶段一不做，但预留接入端口 |
| **LLM 调用** | 单次调用产出全部（不分三段 pipeline） |
| **新内容题** | 固定 2 道 |

**后果 20**：21 天只能读完第一章约 1/4。不影响成功指标（指标是连续打卡而非读完），但影响进度感 ⇒ **进度条按小节呈现**，让完成感来自"读完 1.1.3"这种可达成单位。
**后果 21**：预留乔布斯传端口 ⇒ 生成器需要 `SourceAdapter` 接口（SICP 是 HTML/Texinfo，乔布斯传是 epub），下游流程与源格式解耦。
**后果 22**：固定 2 道题暴露未定义行为——当日读 4–5 块可产出 8–10 个知识点，只有 2 个被检验，其余算什么状态？（由 D9 补齐）

---

### D9 — 知识点入队 / 进度呈现

| | |
|---|---|
| **决策** | 当日读过的知识点**全部入队**，未被抽中出题的**从更长间隔起步**（box 2 / 7 天） |
| | 进度**小节 + 整章百分比同时显示** |

**正面副作用**：当日 8 个知识点中 2 个在 1–3 天后到期、6 个在 7 天后到期，**复习负载自动错峰**。
**残留张力**：未出题的知识点是未经验证的，给更长间隔等于假设已掌握——这是 D5 拒绝的"虚假掌握"的弱化版。可接受，但起步位不应高于 box 2。

---

### D10 — "一天"的边界

| 方案 | 结果 |
|---|---|
| **偏移自然日**（凌晨 4:00 为界） | ✅ 贴合"睡前读书"的实际作息 |
| 本地时区自然日 | ❌ 23:50 + 次日 00:10 各读一次会被误算成连续两天，实际跳了近 24 小时 |
| 滚动窗口（36 小时内算连续） | ❌ 最不易断，但"连续天数"失去日历意义 |

**派生规格**：`checkin` 事件必须存**已换算的打卡日**，不能只存时间戳后期再算——否则改配置会静默重写历史 streak。

---

### D11 — 项目命名

**kuibu（跬步）**，出自「不积跬步，无以至千里」。CLI 命令名同为 `kuibu`。

选择标准：① 命令要连敲至少 21 天，长度成本真实存在；② 仓库名不需要全局唯一，不必为"没被占用"牺牲名字质量。
候选还有 `cairn`（登山石堆路标，与"不惩罚、只可视化"的定位吻合）、`ebb`（Ebbinghaus + 退潮双关，最短）。

## 3. 过程中的三次自我修正

留档的价值不在于决策对不对，而在于**差点错在哪里**。

### ① 漏掉了"简答题 + 自评"这个选项

Claude 最初把题型写成"选择题 vs 需要 LLM 判分的简答题"的二选一，遗漏了 Anki 用了十几年的第三条路：简答后显示参考答案、由用户自评。这条路不需要网络，且对 SICP 这类内容的检验强度明显高于选择题。
补充后 Qian 仍选了纯选择题（理由是不想在 CLI 里输入文本），但这是在完整选项下做的选择，而非被遗漏所限。

### ② SICP 与 session 设计的潜在矛盾，Claude 该早指出而没有

SICP 的价值高度依赖**动手做练习**，而 15 分钟 session 的设计里（读 + 选择题 + 打卡）根本没有"写代码"环节。用 SICP 跑 21 天的可能结局是：打卡成功了，SICP 什么也没学会，进而对整个工具失去信任。
叙事性内容（乔布斯传）没有这个矛盾，代价是版权导致包进不了公开仓。
Qian 知情后仍选 SICP 第一章。**这个矛盾未被消除，只是被知情接受了**——如果实际用起来出现"读了但没学到"的感觉，回来看这一条。

### ③ "单次 LLM 调用产出全部"在整本书粒度上工程不可行

SICP 第一章约四万词，切成 2–3 分钟的块约 150–200 块。一次输出全部块 + 知识点 + 题目将达几百 KB，远超单次输出上限，且截断后无重试粒度。
保留原意图（三件事共享上下文、不搞三段 pipeline）的可行解是**把"单次"的粒度从整本书降到一个小节**。

附带确立了一条重要约束：**LLM 只输出块的边界索引，不复述原文**。理由一是输出量从几百 KB 降到几 KB，二是防止 SICP 的 Scheme 代码被 LLM 悄悄改写。
